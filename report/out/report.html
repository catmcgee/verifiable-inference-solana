1 · STREAM anchor — the bandwidth the encryption eats

Median STREAM triad bandwidth on the box (theoretical: ~614 GB/s from 12× DDR5-6400). CPU LLM decode is memory-bandwidth-bound, so this is the mechanism the TEE tax is measured against. The headline number is the matched pair — two identical 32-vCPU VMs differing only in SEV state: SEV-ES AES memory encryption costs 26% of deliverable bandwidth (346.2 → 256.1 GB/s). Note this 26% is the bandwidth tax; the actual single-stream decode tax below is far smaller because a single decode stream does not saturate the bus. The SNP CVM anchor (376.9 GB/s, KDS-verified, separate run) is shown for context only — a different kernel/day, not a matched SEV-off↔SNP pair, so no SNP tax is claimed from it.

2 · TEE inference tax — overhead per model, matched cell

The measured SEV-ES inference tax, at the one cell where legs A and B were run identically (single-stream, 32 threads, short prompt; concurrency 1). Tax = (median tokens/s leg A − median tokens/s leg B) / leg A. (8b-q8 were not run on both legs at this cell, so no tax is shown for them.)

The result is the surprising part: decode throughput is taxed only about 2% at its worst here — far below the 26% STREAM bandwidth tax above. The reason is in that STREAM number: single-stream decode at 32 threads does not saturate memory bandwidth, so SEV's encryption cost on the memory path hides in the slack. The 26% STREAM figure is the ceiling a fully bandwidth-saturating workload (many concurrent streams, or a much larger model) would climb toward — not the tax a single decode stream actually pays. Measuring that ceiling needs a concurrency/thread A/B sweep on leg B, which has not been run (leg B has one cell only); this chart does not extrapolate to it.

8 · Break-even — the premium verification must command

Same box, same watts, same hour — the only thing SEV changes is tokens delivered per hour, so premium multiplier = cost_B / cost_A = tokens/s_A ÷ tokens/s_B. Reading: at the measured single-stream cell the premium is only a couple of percent (and for bitnet-2b the sign is negative — B measured marginally faster, i.e. within noise), so a buyer who values hardware-attested inference at even a few percent clears break-even. That is the floor: a bandwidth-saturating deployment would move the premium up toward the 26% STREAM ceiling, but that regime was not measured on leg B and is not asserted here. (Single-stream, 32 threads. Receipt costs are per-request, not per-token, listed separately in the attestation section; at devnet fees they are noise per 1M tokens.)

9 · Honest limits

What is and isn't protected, stated plainly. "Encrypted" is layered.

  • Memory is encrypted (SEV-ES), attestation is not yet: guest RAM + register state are encrypted with a per-VM key, so the operator can't read weights/prompt/KV-cache from memory. But we run SEV-ES, not SNP — there is no signed runtime report, so a remote party can't verify the enclave is genuine (grade launch-only). SNP closes this; it's the linchpin, and its guest boot is in progress.
  • Input can be end-to-end private; output too (opt-in): HPKE seals the prompt to the enclave key; the attestation-gated /v1/chat_e2e session seals prompt and response under a key the operator never holds. Default TLS mode decrypts at the terminator — the sealed path is what closes that.
  • Metadata leaks: request timing, sizes, model choice, token counts, and cost are visible to the operator/network even when the payload is sealed. Traffic analysis is not addressed.
  • Model weights are public by design — hashed into the receipt, not hidden. Leg C (Claude proxy) is deliberately not private: Anthropic sees plaintext; it's the honest control.
  • On-chain is hashes, not content: only sha256(prompt), sha256(response), model hash go to Solana — a commitment, not the text (an adversary who guesses the text can confirm it).
  • Trust root is AMD: the ASP/PSP, the memory AES engine, and (for SNP) the VCEK→ASK→ARK signing chain. "Trust AMD silicon instead of the operator," not "trust nobody." SEV-ES side channels (ciphertext, single-step) and the lack of memory-integrity (that's SNP's RMP) are not mitigated.
  • When the GPU arrives: these CPU numbers vs published H100-CC (<5–7%, PCIe-bound) and Blackwell TEE-I/O (near-zero) — projection only, clearly labeled; and tachyon zkML (integrity, not privacy) resumes on the 8×B200s.

Method notes

Aggregation is median throughout, with p99 where tails matter (ITL, attestation phases). Harness convention: n ≥ 5 runs per cell with the first 2 discarded as warmup before logging (kept samples carry ids s03…). Legs A and B differ only in SEV state: same kernel, model files, thread pinning (numa_policy recorded per request), and runtime versions. Leg D encodes the ladder rung in the model field because the frozen v1 schema has no rung field. Charts derive exclusively from the two input files; every chart lists the run_ids behind it.
